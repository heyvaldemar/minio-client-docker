# Security Policy

## Supported versions

| Tags | Status |
|---|---|
| `2025.8.13` and `latest` | :white_check_mark: rebuilt every week |

Fixes ship in the next build; nothing is patched in place. A build that still carries a critical or high finding with a fixed version is not published (`scripts/cve-gate.sh`).

## What can be fixed here

mc is MinIO's, and MinIO archived it after RELEASE.2025-08-13T08-35-41Z: no fix to mc's own code will come from upstream. This image rebuilds that release and changes only what a rebuild can change: Debian's packages, the Go it is built with, and the Go modules it links, raised in `patches/mc-go-modules.patch`. A vulnerability in mc's own code is reported here all the same, and the advisory will say plainly whether a module bump can remove it or not.

## Reporting a vulnerability

Report privately through GitHub: **Security → Report a vulnerability** on this repository (private vulnerability reporting is enabled). Email to v@valdemar.ai also works. The process is described at [heyvaldemar.com/security](https://heyvaldemar.com/security/).

You can expect an acknowledgment within 7 days. This project does not operate a bounty program; researchers who submit valid, responsibly disclosed reports receive public credit in the release notes and the changelog.

Please do not open public GitHub issues for security reports. A vulnerability in a Debian package belongs to Debian; one in Go or a Go module, to its project, and the fixed version then reaches this image by a bump here.

## Supply chain verification

Every published image digest is signed with cosign using Sigstore keyless OIDC issued to this repository's GitHub Actions workflow. SBOM (SPDX, generated by BuildKit) and SLSA build provenance are attached to every image, and build provenance is attested in GitHub Attestations. mc is built from source at a pinned commit, with every Go module checked against go.sum.

```bash
cosign verify heyvaldemar/minio-client:latest \
  --certificate-identity-regexp "https://github.com/heyvaldemar/minio-client-docker/.*" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"
```

## Credentials

The repository holds no credentials. Publishing uses the `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` repository secrets; signing is keyless. The tests make a throwaway MinIO root user and password for each run and never print them.
